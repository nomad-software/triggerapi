# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

TriggerAPI is a desktop client for making REST API, GraphQL and gRPC calls, calling the tools of MCP servers and talking to WebSocket servers, inspired by Postman. It is written in Go with a Qt 6 GUI via the [miqt](https://github.com/mappu/miqt) bindings.

REST, GraphQL, gRPC, MCP and WebSocket requests, environments, saved requests in folders and the history of the requests sent are implemented.

## Compatibility of saved files

Every change must stay backward compatible with existing request files (`requests.json`). A file written by any earlier version must load with nothing lost, and nothing the format or the UI already allows may be taken away unless the user asks for it. Add new data as optional fields (`omitempty`), or in a section or file of its own, so that a file without it reads and writes as before. Normalise old shapes when loading rather than rejecting them, and give every change to the format a test that loads a file in the old format. Check the git history before deciding that something was never supported. The handling of old formats stays, cruft or not, until the user decides to settle on a cleaner format once the program is mature.

## Technical debt

Pay technical debt down as part of every feature and fix, rather than leaving it for later; do not let cruft build up. While working on something:

- Before adding a case for a request type, a colour, an import kind or anything else that comes in kinds, look for the table or interface that already lists them (`requestTypes`, `Window.uis`, `colourKinds`, `tokenKinds`, `importSources`, ...) and extend it; if there is none and the same switch would appear a second time, make one.
- When code being added is like code already there, share it instead of copying it (see `sidebar.go`, `requestui.go`), and remove what the change leaves unused.
- Keep files to one concern; split one that grows a second rather than letting it sprawl (as `window.go` was split into `windowrun.go`, `windowsettings.go`, `windowworkspaces.go` and `windowtabs.go`, and `requesttree.go` into it and `requesttreesearch.go`, `requesttreedrop.go` and `requesttreeimport.go`).
- Free what Qt constructors make once it is no longer needed (see Memory under miqt conventions), and keep `go vet` and `staticcheck` clean.
- Keep this file, the README and `docs/screenshot.png` (`make screenshot`) in step with the code in the same change.
- Anything made to help with the work that is worth running again, such as a generator or a script, goes in the repository with a make target or a note here, never only in a scratch folder.
- Refactoring changes no behaviour. Add tests first where what is being refactored is not covered, and report a bug that is found rather than changing behaviour to fix it unasked.

## Architecture

Packages under `internal/`; only `ui` depends on Qt.

- `rest` is the HTTP engine. `rest.Request` holds everything in the request UI (method, URL, params, headers, auth, body type, raw body, form fields), including fields the chosen auth/body type does not use, so it round-trips through JSON without loss. `Request.Build` turns it into an `*http.Request` and `rest.Send` returns a `rest.Response`. `Request.Options` (a time limit, whether redirects are followed, what a stream of events is given to as it comes, and the `network.Client` it is sent with, which the curl command follows and `Timing` records the proxy and unchecked certificate of) says how it is sent and is not saved with it: the caller sets it, and `Send`, `Curl` (`--max-time`, `--location`) and `RunCurl` go by it; a request that takes too long fails with `context.DeadlineExceeded`. `Send` attaches an `httptrace` tracer (`Tracer` in `timing.go`, which `rpc.Invoke` uses too, so `Timing` takes the TLS from the connection where it is given no response) and gives the response a `Timing`: a `Phase` (start and end from when the request began) for each `Stage` there was, in the order of `rest.Stages` (redirects, DNS, connect, TLS, send, wait, download; only the last request is broken down, the time before it being the redirects, and DNS, connect and TLS are left out for a connection that was reused), with the number of redirects, whether the connection was reused, the server's address and the TLS version and cipher. `RunCurl` asks curl for its times with `--write-out` (`curlTimes`, written to stderr on a line of its own, which `splitCurlTimes` takes out of the reason for a failure); curl adds up the times of every request where there are redirects, so then only the redirects, the wait and the download are given. `Timing` is `omitempty`, so a response kept in the history from before has none. A response whose Content-Type is `text/event-stream` (`IsEventStream`) is a stream of server-sent events (`sse.go`): `Send` reads it as it comes (`readStream`, with `eventParser` reading the lines as the HTML standard has them), keeps the stream as received in `Body` and the events in `Events` (an `Event` is its time from the start, type, last ID and data), gives the response so far to `Options.Stream` once the headers have come and after each event, and ends when the server ends it or the context is done, with how it ended in `Interrupted` (`StreamStopped`, or the error), returning the response and no error either way. The time limit is kept by a timer rather than the context, so that it is on the headers alone of a stream; a request that reaches it is still `context.DeadlineExceeded`. `Events` and `Interrupted` are `omitempty`. `ParseEvents` reads a whole stream, which `RunCurl` does, so those events have no times, and `StreamEvents` gives the events, read from the body for a response kept in the history from before they were kept. `Text` of a stream is `EventLog` (each event as `FormatEvent` has it), and `Document` is what values are captured from: the body, or the data of the last event. `rest.ParseCurl` goes the other way, reading a curl command (as `Curl` writes one or a browser copies one) into a `Request`: `-X`, `-H`, `-d` and its kinds, `--json`, `-G`, `-I`, `-u`, `-A`, `-e`, `-b` and the address, with the body type from the Content-Type (a form without one, as curl sends it), which is dropped when it is the body type's own, and a lone `Authorization: Bearer` header taken as bearer auth. Options that only say how curl runs are skipped (`curlValues` lists those that take a value, so it is not taken for the address), and a body or headers from a file, `-F` and `-T` are errors. `IsCurl` says whether text starts with the word curl. `rest.Auth` is shared by every type of request: none, basic, bearer or `AuthOAuth2`, whose settings are `Auth.OAuth` (`*rest.OAuth` in `oauth.go`, `omitempty` and nil while nothing of it is filled in, so a file from before reads and writes as it did; the client credentials grant is the empty `Grant` and detecting the client authentication the empty `ClientAuth`, so they too add nothing), and `Auth.Access` (`json:"-"`, never saved) is the access token the caller fills in, which `Header` sends as a bearer token, there being no header without one. Put request-building rules here (default scheme, param ordering, header precedence) so they stay unit-testable.
- `network` says how requests reach their servers (`network.go`, `client.go`, `curl.go`, `explain.go`). A `Config` (kept in the settings as `Network`, as it belongs to the machine and never to a workspace, so nothing shared changes it) is the proxy (`ProxyEnvironment`, empty, for the environment's; `ProxyNone`; or an address, http, https or socks5, which may name a user but never a password), `NoProxy` (names matched as curl's `--noproxy` is: the name and the hosts inside it, a leading `.` or `*.` changing nothing), `MinTLS` (`TLS12` / `TLS13`) and `Hosts`: a `Host` is a pattern (`Match`: a name, `*.name` for the hosts inside it, or `*`), a CA file trusted for it in place of the system's, a client certificate (PEM with its key, or PKCS #12 with `software.sslmate.com/src/go-pkcs12`, as `x/crypto/pkcs12` cannot read the AES files OpenSSL 3 makes; a key in legacy encrypted PEM is decrypted, an encrypted PKCS #8 key is refused with how to convert it), `Insecure`, and an `Address` dialled in its place. `Config.Host` gives the most particular entry that matches (a name before `*.name`, a longer `*.name` before a shorter, then `*`), and only that one applies. `Load` reads the files, asking through an `Ask` for each `Secret` (the passphrase of a key or PKCS #12 file, the password of a proxy), and returns a `Client` even with errors: a request to a host whose files could not be read fails with the reason. `Client` is an `http.RoundTripper` keeping a transport per entry (copies of `http.DefaultTransport`); `Transport` makes one with given protocols for gRPC; `Proxy` and `Unverified` say what a request went through; `CurlOptions` / `CurlConfig` give curl the same options, with the secrets as a configuration on its standard input, never as arguments. `Explain` puts what may be done ahead of an error of reaching a server (an untrusted authority, a client certificate wanted or refused, no TLS, no TLS version in common, a proxy that failed).
- `oauth` gets OAuth 2.0 tokens with `golang.org/x/oauth2`: a `Cache` (`NewCache`, one a window, `Window.tokens`, kept for the session and never in a file, shared by the workspaces) keeps a token for each of the settings it was got with (`key`: everything but the secret and how it is given), `Token` gives the one kept, refreshed with its refresh token once it has expired (or a new one if that fails), or a new one, `Fetch` always a new one, `Kept` / `Forget` what is kept, and `Authorize` fills in `Auth.Access` for an authorization of OAuth 2.0 and leaves any other alone. One token of the same settings is got at a time (`hold`). The HTTP client is given through `oauth2.HTTPClient`. Grants: client credentials (`clientcredentials`), authorization code with PKCE (S256; `listen` opens a server for the redirect URL, which must be `http` to `127.0.0.1`, `[::1]` or `localhost`, a free port of `DefaultRedirect` if none is given, and `callbackHandler` takes the first answer with the `state` sent) and device code. Those two need the user: a `SignIn` is given the page (and the device's user code), and without one they are `ErrSignIn`. `describe` makes the errors of a token endpoint readable. `oauth/oauthtest` is an authorization server for tests with every grant, refresh, and a `/resource` that wants one of its tokens.
- `atomicfile.Write` is how every file the program keeps is written (`jsonfile`, the copies and archives of `workspace`, the desktop entry, a saved response): through a temporary file beside it, flushed to the disk (`Sync`) and renamed into place, and then the folder flushed, so that a crash of the program or of the system leaves the file as it was or as it was to be, never a part of either. Its test has writers and readers race over one file.
- `instance` keeps to one copy of the program running for each user, from `main.go` before Qt starts: it holds a lock (`flock` on `triggerapi.lock`, let go by the system if it dies) and listens on `triggerapi.sock` beside it, in `$XDG_RUNTIME_DIR` or a folder `triggerapi-<uid>` of the user's own (0700, checked) in the temporary folder (`Dir`; elsewhere than Linux and macOS there is no lock). A copy started while it runs (`Claim` returns `ErrRunning`) sends it the desktop's `XDG_ACTIVATION_TOKEN` and leaves; the one that runs (`Instance.Serve`) puts the token in its environment, where Qt's Wayland support reads it, and raises the window (`Window.Activate`). Two copies never write the same workspaces at once. One that holds the lock but does not answer (`ErrNoAnswer`) keeps a new copy from starting; any other failure of the check is warned of on stderr and the program runs.
- `appicon` holds the program's icon, `appicon.png` (`appicon.PNG`, a 256×256 PNG of `appicon.Size`, embedded, so the program needs nothing beside its binary), which `ui.appIcon` loads for the window and the desktop entry installs. It is drawn by `appIconPNG` in the `ui` package (`make icons`), as it is painted with Qt.
- `homedir.Expand` replaces the `~` a path in the settings starts with (the keys of `crypt`, the files of `network`).
- `shell` splits a command line into words as a POSIX shell does (`shell.Split`: quotes, `$'...'`, backslashes and the backslash that joins lines), and does nothing else of a shell. The diff command and pasted curl commands are read with it.
- `env` holds environments (named sets of variables). `Environment.Expand` substitutes `{{name}}` placeholders, leaving unknown ones untouched. A variable whose whole value is a call of a built-in function (`random_uuid()`, `random_int()` / `(max)` / `(min, max)`, `iso_date(n)`, `iso_timestamp(n)`, `unix_timestamp(n)`, `base64(text)`, `sha256(text)`, in `functions.go`) is given what `env.Evaluate` makes of it, afresh on each `Expand`; `Environment.Expander` / `Store.Expander` return a function which makes each such value once, so that it is the same in every part of one request. The text of `base64` and `sha256` is all that is in the brackets, with its placeholders replaced by the other variables (`Evaluate` is given the function that does it): the expander makes every value before it returns (`resolve`, which leaves a placeholder that needs the value being made as it is), so that it only reads from then on. The value of a variable that is not a function is never expanded. The functions are described in the README and nowhere in the UI. `Environment.Set` gives a variable a value, adding it if need be. `Environment.Sort` (`"sort"`, `omitempty`: `SortKey`s, each a column, `SortVariable` / `SortValue` / `SortDescription`, and whether descending, the first deciding) is how the editor shows the variables of that environment sorted, and never changes their order; `Clone` copies it. A `Variable` has a `Description`, which is only for the reader; several variables can have one name, of which the last enabled one is used.
- `completion` has what can be typed at a place in a query or message: a `Completion` (the `Item`s, each a `Label`, the `Detail` shown beside it and the `Insert` typed, and the `Start` and `End` in bytes of what they replace), with `Name`, `NameStart` and `Matching` (the items starting with what has been typed, ignoring case, in order, leaving out one typed in full). `graphql.Schema.Complete` and `rpc.Schema.Complete` make them, and the UI's `completer` offers them.
- `capture` takes a value out of the JSON of a response: `capture.Find(document, path)` gives it as decoded (numbers as `json.Number`), a path not in the document being a `MissingError` (`capture.Missing`) and one that cannot be read, or a document that is not JSON, another error, and `capture.Extract(document, path)` gives it as text (`capture.Text`), where a path is names separated by dots with array indexes in brackets (`data.items[0].id`, `[-1]` for the last, `["a.b"]` for a name with a dot in it). Both `rest.Request` and `rpc.Request` have `Captures`, which are `capture.Rule`s: a variable name, a path and an optional regex (stored as `key`, `value` and `regex`), none of them expanded. `Rule.Extract` takes the value at the path and gives it to `capture.Match`, which keeps what the regex matches, or what its first group does if it has groups; a regex that is not valid or does not match is an error like any other. `capture.PathAt(document, offset)` goes the other way, from a place in a document to the path of the innermost value there (a member's name counts as part of its value), with the last name in the path to call it by.
- `assert` checks responses: an `assert.Check` (`subject`, `path`, `comparison`, `value`, `enabled`) looks at a `Subject` (`Status`, `Time` in ms, `Header` named by the path, `Body` at a capture path or whole, as text if it is not JSON, and `Size` in bytes; `Subjects`, `HasPath`) and compares it (`Comparison`: equals, does not equal, contains, does not contain, matches, exists, does not exist, less, greater, length, empty; `Comparisons`, `HasValue`) with its value, which `Run` expands with the function it is given. `assert.Facts` are what of a response is checked (the UI makes them from each engine's response, as `assert` cannot import the engines that hold its checks), with the status as every name it goes by, any of which equals takes, ignoring case; numbers compare as numbers and objects and arrays as JSON. `Run` returns a `Result` (the check, whether it passed and why not) for each check `InUse` (enabled and of a subject and comparison this version knows), and `Failed` counts those that did not. `rest.Request`, `rpc.Request`, `graphql.Request` and `mcp.Request` have `Assertions` (`omitempty`).
- `rpc` is the gRPC engine, built on the connectrpc libraries (`connectrpc.com/connect` and `connectrpc.com/grpcreflect`) with `google.golang.org/protobuf` for dynamic messages. Do not add `google.golang.org/grpc`. `rpc.Reflect` asks a server to describe itself through server reflection and returns a `Schema` (there is no support for loading `.proto` files); `rpc.Request.Network` (`json:"-"`, given by the caller) is the `network.Client` its transport is made with (`Client.Transport`, with HTTP/2, or unencrypted HTTP/2 without TLS); nil is the environment's proxy and Go's TLS. `rpc.Schema.Complete` (`complete.go`) says what can be typed at an offset of the JSON message of a method: the keys of the message the end is in that are not there yet, by their JSON names, or the values of an enum or a boolean, following keys into messages, lists of messages and the values of maps through a stack of `container`s, and nothing inside protobuf's own types (`isWellKnown`). `rpc.Invoke` sends the JSON messages of the request over a bidirectional stream, closes its side and collects every response, which covers every kind of method. The text of `rpc.Request.Message` is one message, or several for a method that takes a stream of them (`Method.ClientStreaming`): objects one after another, or an array of them, which is never a message (`splitMessages` in `messages.go`, with `rest.SplitJSON`); a method that does not is refused more than one, so the format of saved requests is unchanged. `Schema.Example` gives a method that takes a stream an array of two, and `Complete` completes each message of one after another or in an array. A status other than OK, including a cancelled call, is returned as a `Response`, not an error. Calls are always made in the gRPC protocol (`connect.WithGRPC`); `Response.Protocol` names the protocol the server answered in, read from its `Content-Type` by `rpc.Protocol`, and is shown as the Protocol field. `Response.Timing` (a `rest.Timing`, `omitempty`, so a response kept in the history from before has none) is made by a `rest.Tracer` given to the stream's context, and `Timing.Annotate`d with the network settings: sending is that of every message, and the download from the response's headers to the end of the call. `rpc/rpctest` is a connect-based test server with an Echo service, used by the `rpc` and `ui` tests; `NewStreamingServer` gives it the methods that take a stream of messages too (`Gather`, client streaming, and `Talk`, bidirectional), which `NewServer` leaves out so that the tests of the others are not changed by them.
- `ws` is the WebSocket engine, built on `github.com/coder/websocket`. A `ws.Request` is a URL (`Target` gives it a `ws`/`wss` scheme, assuming `ws://`, and takes `http`/`https` as the same), handshake headers, `rest.Auth` and a text message; `ws.Dial` opens a `ws.Conn` (the context limits only the handshake; a refused handshake's error names the HTTP status), which `Send`s text and `Receive`s messages until it closes, when `ws.Closed` gives the close code and reason (`Normal`, `CodeName`). Messages are `ws.Message`s, sent or received, with their time.
- `graphql` is the GraphQL engine, built on `rest`. A `graphql.Request` is an endpoint, headers, `rest.Auth`, the query, the variables as the text of a JSON object (empty for none; `{{name}}` placeholders in it are expanded before it is parsed, so one can stand for a value without quotes) and `Captures`. `Request.HTTP` makes the `rest.Request` that is sent (a POST of `{"query", "variables"}` as JSON, an error for an empty query or variables that are not an object), which goes through `rest.Send` with the options of a REST request. `graphql.Errors` gives the messages of the `errors` of a response, which can come with any status. `graphql.Introspect` asks the server for its schema with the request's headers and auth and gives it as a `Schema`, which `SDL` gives in the schema definition language (`schema.go`: the root types first, then the others alphabetically, leaving out the built-in scalars and the types of introspection) and `Complete` (`complete.go`) says what can be typed at an offset of a query from: a `reader` reads the query as far as the name being typed, valid or not, keeping the selections (with their types), the arguments being read and what is expected in them, and whether the end is after `on`, `...` or `@`; nothing is offered in a string, a comment or a variable.
- `mcp` is the Model Context Protocol engine, built on the official Go SDK (`github.com/modelcontextprotocol/go-sdk`, imported as `sdk`); use what it provides rather than handling JSON-RPC or the transport by hand. Only the Streamable HTTP transport is supported. stdio is left out on purpose, so that the program never runs anything (a shared request could otherwise run a program); `mcp.Request.Transport` (empty for HTTP, `omitempty`) is there so it can be added. HTTP+SSE is not supported. A `mcp.Request` is the server's URL, headers, `rest.Auth`, what it calls (`Kind`: `tool`, `resource` or `prompt`, empty taken for a tool, and `Name`, the URI of a resource), the arguments as the text of a JSON object, and `Captures`. Since protocol version 2026-07-28 (SEP-2575) MCP is stateless and sessions are deprecated: the SDK's `Connect` asks `server/discover` and sends the protocol version in the `_meta` of every request, falling back to the `initialize` handshake, and the session (`Mcp-Session-Id`) it gives, for an older server. Do not build anything on sessions; they are only kept for those servers. A `mcp.Client` (`NewClient`, given the request with its placeholders replaced and an `Authorizer`, which completes the authorization of each HTTP request, as a token of OAuth 2.0 can be refreshed while the client is in use; the SDK takes an error of the transport for a JSON-RPC one, so the authorizer's is wrapped in an `authError` and taken out again by `with`) connects on first use, with `DisableStandaloneSSE`, gives the HTTP requests the request's headers and auth through its `headers` round tripper (built with `rest.Request.Build`, so the precedence is that of REST), connects again once if an older server has ended its session (`sdk.ErrSessionMissing`), and is safe from several goroutines. `Client.Call` returns a `mcp.Response`: the result as JSON, or a JSON-RPC error (`*jsonrpc.Error`, a response and not an error), the status and headers of the HTTP answer (recorded through a value in the context), the protocol version, the server's name and `Events` (`events.go`, `omitempty`): what the server sent while the call was under way, and asked and was answered, each an `Event` of a kind (`EventProgress`, `EventLogged`, `EventElicitation`, `EventSampling`), with `Text` and `EventLog` for showing them. `Call` is given a `Listener` (nil for none), told each event as it comes, with `Elicit` and `Sample`, which answer what the server asks; without them what is asked is declined, and `ErrDeclined` from `Sample` declines sampling, which fails the call. `calls.go` has the calls under way (`Client.begin` / `end`, a `call` keeping its events): the SDK's handlers belong to the client, so progress is matched to its call by the progress token each call is sent with (`prepare`, which also asks a stateless server for every message logged through `MetaKeyLogLevel`; an older one is asked once with `SetLoggingLevel`, `askToLog`), and what is asked by the context of the call, which the SDK's multi round-trip answers a stateless server in, or else the latest call under way, as an older server asks through its session (whose context has the values of the call it was connected for, so `find` takes it only while that call is under way), as do messages logged. The SDK hands notifications to a queue that the answer can overtake, so `settle` waits a moment for the last of them before the events are taken. `ask.go` makes an `Elicitation` (a message and `Field`s, in alphabetical order as the order the server gave is lost, each string, number, integer, boolean or `FieldChoices`, with `Options` from `enum` / `enumNames` or `oneOf` / `anyOf` constants, a default, whether it is required and the least and greatest, of a number or of the length of a string; `Field.Parse` reads one typed as text) and a `Sampling` (the system prompt, the messages as text, what is wanted of the model) of what the SDK gives, answered with an `ElicitAnswer` (an action and the values) or a `SampleAnswer` (the text and model). Sampling and logging are deprecated since 2026-07-28 (SEP-2577) but servers still use them, so the files using them have a `lint:file-ignore SA1019`. A request to go to a page (URL elicitation) is declined. `ToolError` and `OK` say whether a tool reported an error, and `Outcome` gives the status (OK, Tool error, or the code and its name), the problem and whether it failed, which the response panel and the history show. `Client.Discover` lists the tools, resources and prompts the server has capabilities for, as a `mcp.Schema` of `Item`s, whose `Example` makes arguments from a tool's input schema (with `github.com/google/jsonschema-go`) or a prompt's arguments. `mcp/mcptest` is a Streamable HTTP test server, made with the SDK, used by the `mcp` and `ui` tests, with tools that send their progress and log (`progress`), elicit (`who`) and ask for sampling (`sample`): `NewServer` is stateless, and `NewLegacyServer` gives sessions, as a server from before 2026-07-28 does; the `mcp` tests run against both.
- `history` keeps the requests sent from a workspace (`history.json` in its folder, encrypted like the rest): a `Store` of `Entry`s, newest first. An `Entry` is the time, a copy of the `collection.Request` as composed (with its placeholders and its name if it was saved: the copy is the record), the `Store.Path` of the saved request it was sent from (best effort: it may have been moved or removed since), the name of the active environment, the URL with its placeholders replaced (the only part kept so, as the others often hold secrets), the duration, and the `Error` there was or one of the responses: `HTTP` (`*rest.Response`, for REST and GraphQL), `GRPC`, `MCP` or `WebSocket` (a `history.WebSocket`: the messages, the handshake headers and time, and how the connection ended). Those engine responses and `ws.Message` have JSON tags for this. `Store.Add` leaves out a body larger than `MaxBody` (copying the response, recording its size in `Omitted`; the events of a stream or of an MCP call count towards it, and go with it) and `Keep` drops the oldest beyond the limit of the settings and to keep the bodies within `MaxTotal`, as the whole file is written again each time it is saved. What differs between the kinds of response is in one place: `Entry.response` gives the one there is as a `response` (its status, text, size, and `omit`, which gives the entry a copy without the body), so a new kind is a type there and a case in it. `Entry.Status` and `Title` are what the list shows, `Matches` what its search looks at, and `Text` the body of the response as it is shown (`rest.Response.Text`, `mcp.Response.Text`, `ws.Log`, which the response panels use too), which is what is compared. `Entry.Assertions` (`omitempty`) are the results of the assertions of the request.
- `collection` holds saved requests: a `Store` of `Folder`s, each with `Request`s. A `Request` has a name, a `Type` (`rest`, `grpc`, `websocket`, `graphql` or `mcp`) and exactly one of an embedded `*rest.Request` (stored flat beside the name, which is also the format from before there were types), `GRPC *rpc.Request`, `WebSocket *ws.Request` (`json:"websocket"`), `GraphQL *graphql.Request` (`json:"graphql"`) or `MCP *mcp.Request` (`json:"mcp"`); `Load` normalises this (`normalise`, which `New` uses too, so a new type needs only its case there and its constructor; `SetContent` copies everything but the name). Check `Type` before touching either. A `Folder` holds requests and other folders, to any depth (`Folders` then `Requests`), and records whether it is shown open (`Open`), which the tree sets as folders are opened and closed and which is never saved (`json:"-"`), so every folder starts closed at startup; a `collapsed` or `favourite` mark in a file from before is ignored and not written again. Selecting a request in the tree (as choosing its tab does, through `requestTree.selectRequest`) opens the folders it is in, as Qt's `scrollTo` expands them and `setCollapsed` records it; the store has only folders at its top level, never requests. The store also has `Sets`, each a name and the `*Request`s it holds, from any folders, in order; `Store.MarshalJSON` / `UnmarshalJSON` write them in a `sets` section (left out when there are none) with each request as its `Store.Path`, `LoadWith` finds them again (leaving out those not found), so renaming or moving a request keeps it in its sets, and `Store.PruneSets` takes out those removed (`requestTree.remove` calls it). Folders and requests are held by pointer so they keep their identity when others are removed. `collection.New` makes the empty request of a type (a REST one is a GET), `Request.SetContent` gives a request what another holds while keeping its name, and `Store.FoldersIn`, `Insert` and `Delete` act on the folders inside a folder, or at the top level for nil, so that callers need not tell the two apart.
- `openapi` turns an OpenAPI 3 or Swagger 2 document (JSON or YAML, read with `gopkg.in/yaml.v3`) into a `collection.Folder` of REST requests: one per operation, in subfolders by first tag. Unknown values become `{{placeholder}}`s. It is tolerant of missing references. An OAuth 2.0 scheme becomes `AuthOAuth2` by the first flow it has of client credentials, authorization code and device authorization (`securityScheme.oauth`, with Swagger 2's `application` and `accessCode` flows, the scopes of the requirement, and the client as `{{clientId}}` / `{{clientSecret}}`), and a bearer `{{token}}` otherwise. ## UI tests

The tests of a feature are in the file named after its source (`rest_test.go` for `rest.go`, `requesttreesearch_test.go` for `requesttreesearch.go`, and so on); put a new test there, and a helper used by tests of more than one feature in `helpers_test.go`. `internal/ui/ui_test.go` holds only the harness and the fixtures of a test window: it has a `TestMain` that creates the `QApplication` offscreen and runs the Qt event loop on the main thread while tests run on another goroutine. A test that hangs is killed by `-timeout` (`go test ./internal/ui/ -v -timeout 90s` names it). Tests must pass `NewWindow` the `Files` of `testFiles(t)`, whose settings file names the keys made in `TestMain` (a test which makes its own `Files` or settings file needs `saveTestKeys` or `PublicKey: testPublic, PrivateKey: testPrivate`, as a window without keys loads nothing, and `closeWindows(t)` after its folder is made, which `testFiles` calls: it closes the windows when the test ends, as one left open saves its settings when the tests are over, into a folder that has gone, and says that it could not), read what a window saved with `loadEnvs` / `loadRequests` / `loadHistory`, which wait for `writer` (`writer.Flush()`, which a test reading a workspace's file any other way calls first) and decrypt with those keys (`testFiles(t).Files`; its `Environments`, `Requests` and `History` are the paths of the files of the one workspace it makes, named Default), replace `requestTree.confirm` and `envList.confirm` (asked before an environment is removed) rather than let a modal dialog open, set `testRequestType` (or use `addRequestOf` / `addGRPCRequest`) to choose the type of an added request, set text into a field typed into and call `Window.commit` (or send Return or a loss of the keyboard, `pressReturn` / `loseKeyboard`) before looking for it in the store, use `waitFor` for asynchronous results, create and touch widgets inside `mainthread.Wait` / `mainthread.Wait2`, never call `t.Fatal` inside them when the test goes on to wait for something (it ends the goroutine of the Qt main thread's callback, and the run hangs), and poll for asynchronous results rather than blocking the main thread.

Releases for Linux are an AppImage, built by `.github/workflows/appimage.yml` (on a `v*` tag, which makes a release, or by hand) in an `ubuntu:22.04` container, so that it runs on glibc 2.35 and later; glibc itself is not bundled. Releases for macOS are an app for Apple Silicon alone (arm64), in a disk image, built by `.github/workflows/macos.yml` on `macos-14` with Homebrew's `qtbase` (which has the pkg-config files the bindings are built with; ## Building with miqt

- miqt is cgo: building needs a C++ compiler and the Qt 6 development headers (found via `pkg-config`, e.g. `Qt6Widgets`).
- The first build of `github.com/mappu/miqt/qt6` compiles the whole binding and takes about 5 minutes; later builds use the Go build cache and are fast. Use a long timeout for the first build, and avoid `go clean -cache` or changing cgo flags, which forces the full rebuild.
- That build prints a large volume of `-Wsfinae-incomplete` warnings from the Qt headers. They are noise; search the output for `error` instead of reading it.
- Linux is the only platform tested by hand for now. There is a macOS release for Apple Silicon (see Commands), so avoid adding Linux-only assumptions (paths, shell-outs, X11/Wayland specifics) where a portable Qt or Go API exists.
- `README.md` lists the packages needed to build on each distribution; keep it in step if the Qt modules used change (currently only `Qt6Widgets`).

## miqt conventions

- Import as `qt "github.com/mappu/miqt/qt6"`. Use the `qt6` package, not `qt` (which is Qt 5).
- C++ overloaded constructors and methods become numbered Go functions (`NewQMainWindow2()`, `NewQLabel3("text")`). Check the miqt package source or docs for the right overload rather than guessing the number.
- Static methods are `Class_Method` (`qt.QApplication_Exec()`); signals are connected with `OnSignalName(func(...))`.
- Qt widgets must only be touched from the main (GUI) thread. Network calls run in goroutines and hand results back with `mainthread.Start` from `github.com/mappu/miqt/qt6/mainthread`.
- Memory: objects from `NewQ...` constructors are never freed by Go, so short-lived ones need `Delete()`. Value types returned by methods and static functions (`ToQVariant()`, `QFontDatabase_SystemFont()`, ...) already have a finalizer (`GoGC()` in the miqt source); calling `Delete()` on those is a double free that crashes at a later garbage collection. Check the generated function before deleting anything.
- Do not use methods that return a Qt value type by value rather than by pointer, such as `QPlainTextEdit.FirstVisibleBlock()` and `BlockBoundingGeometry()`: miqt returns a copy of a struct whose C++ object is freed when the original is garbage collected. Use an equivalent that returns a pointer (`CursorForPosition(...).Block()`, `CursorRect(...)`).
- A finalizer runs on a thread of the garbage collector, not the GUI thread. That crashes for a `QTextCursor` (`TextCursor()`, `CursorForPosition(...)`), which is on the list its document keeps of its cursors: being taken off it from another thread while the GUI thread changes the document corrupts the heap. Free every text cursor a method returns with `release` (`release.go`), which removes the finalizer and deletes it at once. `TestTextCursorsWhileCollecting` covers this.
- Pass a widget to a layout or container through its embedded base (`button.QWidget`, `layout.QLayout`, `window.QObject`).
